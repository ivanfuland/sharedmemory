### 1. StaticTokenVerifier

```python
from fastmcp.server.auth.providers.jwt import StaticTokenVerifier
```

**Status: ✓ CONFIRMED** — import succeeds, class exists at this path.

Constructor signature:

```python
StaticTokenVerifier(
    tokens: dict[str, dict[str, Any]],
    required_scopes: list[str] | None = None,
)
```

`tokens` dict format — each key is the raw bearer token string, value is a metadata dict:

```python
{
    "my-secret-token": {
        "client_id": "cass-mcp-local",   # required
        "scopes": ["read", "write"],       # required
        "expires_at": None,               # optional; unix timestamp or None for no-expiry
    }
}
```

Instantiation example (for B3 server.py):

```python
verifier = StaticTokenVerifier(
    tokens={
        os.environ["CASS_MCP_BEARER_TOKEN"]: {
            "client_id": "cass-mcp-local",
            "scopes": [],
        }
    }
)
mcp = FastMCP("cass-mcp", auth=verifier)
```

## Notes for B3

- `StaticTokenVerifier` is documented as "for development/testing only — tokens stored in plain text". For the cass-mcp use case (local loopback, single known bearer token loaded from env var), this is acceptable.
- The `get_access_token` dependency can be omitted from tool signatures if you don't need per-request caller identity — auth enforcement happens at the transport layer automatically once `auth=verifier` is set on `FastMCP`.
- `infra/cass-mcp/*.env` is gitignored (added in this task) — store `CASS_MCP_BEARER_TOKEN` there.
